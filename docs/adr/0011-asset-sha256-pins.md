# 下载资产供应链钉：sha256 与版本同文件钉死

starship / lazygit / nerd-fonts 三个直接下载的资产原先只钉版本不钉内容——release 资产被替换时无从发现（版本号对了、内容可以不对）。解法：sha256 与版本钉在**同一个钉子文件**（单一来源不变），行格式 `sha256 [amd64|arm64] <64位hex>`（JetBrainsMono.zip 无分架构，用无 arch 行）；install-user-tools 下载后先校验再落盘，不符即拒绝安装并报「疑似供应链异常」。升级钉子的动作从「改一行」变为「版本行 + sha 行同次重算」，仍是单文件单次编辑。

边界：vp / uv / docker 走官方 curl|sh 安装器，资产不是直接下载，不在此钉（信任锚是安装器域名本身）；apt 包由发行版源签名兜底，不重复钉。WDC 统筹不受影响：vp-version 无 sha 行，同值约定不变。

拒绝的替代：独立 `configs/*-sha256` 文件（文件数翻倍，违背钉子单文件直觉）；GPG 签名验证（release 资产无统一签名基建，sha256 已覆盖「内容替换」威胁面）；钉子缺 sha 行时硬失败（升级流程允许版本先行、哈希随后补的中间态，INFO 提示补齐即可）。
